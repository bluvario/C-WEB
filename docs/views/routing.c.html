Routing

Every page file becomes a route. The mapping is mechanical, so there is no separate route table to keep in sync.

How views become routes

FileRoute
views/index.c.html/index and /
views/hello.c.html/hello
views/admin/users.c.html/admin/users
views/404.c.htmlnot a route — the not-found page
views/layout.c.htmlnot a route — the wrapping layout
views/partials/*.c.htmlnever routed — fragments only

Every route is registered for GET and POST. The handler is the same either way, so a page branches on req->method (see Requests).

Not-found handling

Anything no route claims falls to the views/404.c.html page, answered with a 404 status. When a static dir is mounted it gets first refusal before the 404 page runs, so missing files still hit your custom 404.

There is always a 404 answer even without a 404 page file.

Static files

Pass a static/ dir to cweb build / cweb serve and it is mounted at /* behind the pages — any path no page claims is served from disk with the right Content-Type. A --static-cache N flag stamps Cache-Control: max-age=N on them, and ETag / Last-Modified validators answer 304 for you.

cweb build views out . static
./out/server --port 8080 --static-cache 3600

Route captures

When you hand-wire a router in a main.c (instead of going through the page-file convention), patterns may contain <name> captures. They match one path segment and land in params under their name:

router_add(&r, HTTP_GET, "/notes/<id>", show_note, NULL);
router_add(&r, HTTP_GET, "/users/<user>/books", list_books, NULL);

Captures are raw path segments — percent-encoding is not decoded for you, so decode them with url_decode_into before trusting them. The router is intentionally spartan: a terminal * pattern matches anything (that is how the generated 404 fallback is wired), and the first match wins, in registration order.

Captures in page files? The page-file convention routes each file to its own exact path, so captured routes are a hand-written main.c feature. The generated server is one router with the page routes registered in sorted order, then the static mount, then the 404 fallback.

Per-route timeouts

The generated server sets a default read deadline (default 408 on a stall). Give a specific route its own budget with --route-timeout /path/to/route 5000 (5 seconds in milliseconds). In a hand-written router, use router_add_timeout or router_set_timeout.

Putting it all together by hand

The library router (router.h) is a small, plain object. A hand-built app wires one up directly:

Http_Router r;
router_init(&r);
router_add(&r, HTTP_GET, "/", home_page, &store);
router_add(&r, HTTP_GET, "/style.css", static_css, NULL);
router_add(&r, HTTP_GET, "*", not_found_page, NULL);

Http_Server_Config cfg = {0};
http_serve(listener, router_dispatch, &r);

router_dispatch is an Http_Handler_Fn, so it drops straight into http_serve/http_serve_config, or into a middleware chain (see Middleware).
