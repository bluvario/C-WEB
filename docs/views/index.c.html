C-WEB

C-WEB is a web framework where the backend is written in C, embedded directly in your HTML files. A `.c.html` page mixes markup and C code; the framework compiles those files into a native server binary with a built-in HTTP stack, HTTP/2 (h2c and h2 over TLS via ALPN), TLS, WebSocket, SSE, sessions, middleware and a file-backed database. No interpreter, no dynamic language, no runtime to deploy — just one binary.

What a page looks like

A page is HTML with C spliced in between <?c ... ?> tags. Everything outside the tags is output verbatim; the C inside decides what gets printed.

<!DOCTYPE html>
<html>
<head>
  <title>My site</title>
</head>
<body>
<?c for (int i = 0; i < 5; i++) { ?>
  <p>Hello number <?c= sv_from_cstr(count[i]) ?></p>
<?c } ?>
</body>
</html>
Note: every page answers GET and POST with the same handler, so a form posts straight back to the page that rendered it. Check req->method to tell them apart.

What you get out of the box

  • The cweb CLI — scaffold, build and serve an app with three commands.
  • Templates — layout wrapping, partials, HTML escaping, date helpers.
  • HTTP stack — keep-alive, chunked bodies, streaming, HTTP/2 (h2c and TLS), TLS.
  • Router — <name> captures, a catch-all 404, per-route timeouts.
  • Sessions — server-side store, flash messages, CSRF protection.
  • Middleware — security headers, rate limiting, gzip, ETags, CORS, request signing.
  • WebSocket and SSE — both protocols supported, no third-party server.
  • A database — a tiny file-backed key-value store, no daemon needed.
