Pages and templates

A page is a plain HTML file with C code spliced in. The framework compiles it into a function — static void page_xxx(Http_Request *req, Http_Response *res, Str_Map *params, void *user_data) — that gets registered with the router. The .c.html extension marks the file for compilation; the .html part is what you actually read.

The three tags

TagMeaning
<?c ... ?>Raw C statements, executed as-is. req, res, params and user_data are in scope, plus stdio/stdlib/string/stdint.
<?c= expr ?>Append expr to the body as-is; expr must be a const char *.
<?h= expr ?>Append html_escape_into(res->body, expr); expr is a String_View.

Everything outside the tags is output verbatim, in order. The generated handler sets Content-Type: text/html before any of the above runs.

A page that uses them all

<h1>Hello</h1>

<?c
  const char *name = strmap_get_cstr(params, "name");
  if (name == NULL) name = "stranger";
  int n = 3;
?>

<p>Hi <?h= sv_from_cstr(name) ?></p>

<?c for (int i = 0; i < n; i++) { ?>
  <p>Number <?c= sv_from_cstr("one") ?></p>
<?c } ?>
Escape user input. <?c= ... ?> does not escape anything. Any value that came from a request — form fields, query strings, database contents — must go through <?h= ... ?> so HTML metacharacters cannot be injected. The rule of thumb: your own constants can use <?c=; everything else gets <?h=.

What is in scope

  • req — the parsed Http_Request (method, path, headers, body… see Requests).
  • res — the Http_Response you are building (see Responses).
  • params — the route captures and merged form/query params (see Routing).
  • user_data — for generated apps, the shared Http_Session_Store.

The compiler also pre-includes the frameworks' headers, so the strings (strmap_*, sv_*), escaping, validation, flash, CSRF, sessions, params and template helpers are all available without you adding an #include.

Reading params

Query string, form fields, and route captures all land in params (route captures last, so they win). Read them with strmap_get_cstr:

<?c
  const char *note = strmap_get_cstr(params, "note");
  const char *id   = strmap_get_cstr(params, "id");   // from a <id> capture
?>
<p>Note: <?h= sv_from_cstr(note != NULL ? note : "") ?></p>

Layouts

A views/layout.c.html page is a convention: it is compiled like a page but never routed. Instead, when present it wraps every other page. The page renders into a per-thread capture, then the layout runs and draws its body with that markup spliced into the middle:

<!DOCTYPE html>
<html>
<head><title>My site</title></head>
<body>
  <header>...</header>
  <main>
    <?c cweb_tpl_layout_emit(res); ?>
  </main>
</body>
</html>

One layout per app; it shapes every page including the 404 page. Escape hatch: a page can set res->no_layout = 1 to render itself without the wrapper.

Partials

Files under views/partials/ are compiled and declared in the generated pages.h but never routed. Any page can render one as a fragment by calling it like a function:

<?c page_footer(req, res, params, user_data); ?>

The function name comes from the file: views/partials/footer.c.html becomes page_footer.

Time helpers

Timestamps want more than raw arithmetic. The template helpers render them and append to the response directly — they are plain text, so use them via <?c ... ?>, not <?c= ... ?>:

<?c cweb_tpl_date_local(res, last_seen); ?>  <!-- 2026-09-12 09:30:00 -->
<?c cweb_tpl_now(res); ?>                     <!-- local now stamp -->
<?c cweb_tpl_strftime(res, "%Y-%m-%d", t); ?> <!-- arbitrary strftime -->
<?c cweb_tpl_date(res, t); ?>                 <!-- RFC 7231, GMT -->

Handling POST

Every route handles GET and POST. To tell them apart, examine req->method and, for a form POST, read the merged params. A full round-trip — render a form, handle the POST, flash a message, redirect — looks like:

<?c
  Http_Session_Store *store = (Http_Session_Store *)user_data;
  Http_Session *sesh = http_session_from_cookie(store, req, "app_session");
  if (req->method == HTTP_POST) {
      const char *name = strmap_get_cstr(params, "name");
      if (name == NULL || name[0] == '\0') {
          http_flash_set(sesh, "error", "A name is required.");
      } else {
          http_session_issue_cookie(res, "app_session",
                                    http_session_create(store, -1), NULL);
          http_flash_set(sesh, "ok", "Saved.");
          http_response_redirect(res, HTTP_303_SEE_OTHER, "/");
          return;
      }
  }
?>

<?c size_t shown = http_flash_render(res, sesh); ?>

<form method="post">
  <input name="name">
  <button>Save</button>
</form>

See Sessions for the session, flash and CSRF machinery in detail.
