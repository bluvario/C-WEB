Streaming

Three ways to push bytes to a client over time, from simplest to most involved.

Chunked streaming

Pick a function that fills a buffer with the next chunk of body. The server chunks the output — you never touch the socket:

static size_t feed_progress(void *buf, size_t cap, void *ud)
{
    Progress *p = ud;
    if (p->done) return 0;              // 0 = stream finished
    size_t n = snprintf(buf, cap, "tick %zu\n", p->tick++);
    return n;
}
<?c
  http_response_set_stream(res, feed_progress, &prog);
?>

Alternatively queue chunks directly from the handler — the server drains them in chunked framing after the handler returns:

<?c
  http_response_stream_write_cstr(res, "part one; ");
  http_response_stream_write_cstr(res, "part two");
?>

Server-Sent Events (SSE)

One HTTP connection, a stream of text events, automatic reconnect by the browser. Build events into a buffer with sse_frame, then hand a producer to the response:

static size_t feed_events(void *buf, size_t cap, void *ud)
{
    Strbuf frame;
    strbuf_init(&frame);
    // write one event per call; time or wait as needed in a real impl
    sse_frame(&frame, sv_from_cstr("{\"h\":1}"), NULL, NULL, 0);
    size_t n = frame.count > cap ? cap : frame.count;
    memcpy(buf, frame.items, n);
    strbuf_free(&frame);
    return n;
}
<?c
  http_response_start_sse(res, feed_events, NULL);
?>

The client sees plain data: ... lines plus a blank separator, exactly per the SSE spec.

WebSocket

For bidirectional traffic, upgrade a handler to a live socket. The pattern: your page (or a route) calls http_ws_upgrade into the response, and the server replies 101 and hands the raw connection to your callback:

static void on_open(Http_Ws_Conn *conn, void *ud)
{
    uint8_t buf[4096];
    Http_Ws_Frame frame;
    while (http_ws_read_frame(conn, &frame, buf, sizeof buf) > 0) {
        if (frame.opcode == WS_OP_TEXT) {
            http_ws_send_text(conn, "echo: ");
            http_ws_send(conn, WS_OP_CONT, buf, frame.payload_len, 1);
        }
    }
    http_ws_send_close(conn, 1000);   // clean shutdown code
}
<?c
  if (http_ws_upgrade(req, res, on_open, NULL) != 0) {
      http_response_set_status(res, HTTP_400_BAD_REQUEST);
  }
?>

The upgrade only succeeds on a genuine WebSocket handshake (GET, Upgrade: websocket, Sec-WebSocket-Version: 13). A convenience loop, http_ws_loop, reads frames for you, answers PING with PONG and CLOSE with a close answer, and calls your message callback for the rest.

  • http_ws_send_text — one convenience call for text frames.
  • http_ws_send_pong — answer a liveness probe.
  • Frames: WS_OP_TEXT, WS_OP_BIN, WS_OP_PING, WS_OP_PONG, WS_OP_CLOSE.

Refreshing the client

The browser side is your choice. A plain script of new EventSource('/events') is all SSE needs; WebSockets use new WebSocket('ws://...'). Helpers exist server-side only — this framework is a backend, not a frontend.
