HTTP/2

C-WEB serves HTTP/2 over cleartext — h2c for short — as a peer of HTTP/1.1, decided per connection. No separate port, no ALPN dance: a client that speaks h2c gets h2c, a client that does not stays on 1.1.

How it is negotiated over cleartext

There are exactly two h2c entry points (RFC 7540 §3.2), and the server handles both:

  • Prior knowledge. The client connects and immediately sends the 24-byte connection preface — PRI * HTTP/2.0\r\n\r\nSM\r\n\r\n — then frames. The server recognizes the magic bytes and speaks h2 from the first byte.
  • Upgrade. The client sends a normal HTTP/1.1 GET that announces the switch in its headers — Connection: Upgrade, HTTP2-Settings and Upgrade: h2c. The server answers 101 and both sides continue in h2.
Note: over TLS, HTTP/2 is negotiated by ALPN instead and happens automatically when OpenSSL is present. h2c is the cleartext flavor; the same framing code path does both.

What you get for free

  • Multiplexed streams over one connection — no more head-of-line blocking between requests.
  • HPACK header compression, Huffman-coded, with the dynamic table really maintained (RFC 7541), not stubbed.
  • The normal request pipeline: your page handlers see an Http_Request exactly like a 1.1 request, so templates, sessions, middleware and streaming all work unchanged.
  • Flow control, per-stream and per-connection, with orderly GOAWAY shutdown.

Streams and your handler

Concurrent streams are transparently multiplexed over the socket. The framework's own limits:

  • Up to H2_MAX_CONCURRENT_STREAMS (100) open streams; beyond that, new streams are refused with RST_STREAM(REFUSED_STREAM) rather than queued.
  • Bodies respect the same --max-body / --body-dir semantics as HTTP/1.1, including the spill-to-disk path.

Is my framework using h2c?

curl speaks prior-knowledge h2c out of the box:

curl --http2-prior-knowledge http://localhost:8080/

Or force an h2c upgrade over a 1.1 request:

curl --http2 http://localhost:8080/

Check a response's HTTP/2.0 200 status line to confirm which protocol answered.

Inside the server

The h2 layer is src/http/h2.c and src/http/hpack.c — framing, HPACK, multiplexing and GOAWAY. It lives in the library like everything else, so a hand-written server can serve h2 by calling h2_serve directly if it ever needs to bypass the top-level connection loop.
