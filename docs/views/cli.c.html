The cweb CLI

build/cweb is the framework's command-line driver. It turns a directory of .c.html pages into a native server, scaffolds new apps, and runs servers with live reload.

Commands

CommandWhat it does
cweb build VIEWS OUT [ROOT [STATIC]]Compile every page under VIEWS into C, emit OUT/main.c and link OUT/server.
cweb serve [--watch] VIEWS [PORT [ROOT [STATIC]]] [FLAGS...]Build into a scratch dir and run it. With --watch, rebuild and restart on any file change.
cweb new APP_DIRScaffold a fresh project: pages, a 404, a layout, a partial and a stylesheet.
cweb versionPrint the framework version.

ROOT (default .) is the cweb checkout holding include/ and build/libcweb.a. When the given path does not hold an include/ dir, the tool walks up to the nearest ancestor that does — so cweb serve views 8080 . static works from inside an app directory next to the checkout.

How pages map to routes

  • views/hello.c.html → route /hello.
  • views/sub/world.c.html → route /sub/world.
  • views/index.c.html → /index and the root /.
  • views/404.c.html → not a route; it becomes the app's custom not-found page.
  • views/layout.c.html → the document shell that wraps every page.
  • views/partials/*.c.html → compiled and declared in pages.h but never routed; pages render them as fragments.

Every route answers GET and POST with the same handler, so a form posts right back to the page that rendered it. See Routing for the full rules.

Server flags

The built OUT/server binary accepts these flags. cweb serve passes anything after the positional arguments straight through, so both paths honor the same options.

FlagWhat it does
--port NListen port, default 8080.
--rate NPer-address budget of N requests a minute (429 past it).
--secureHardening headers on every response.
--gzipCompress compressible response bodies.
--db PATHOpen the file-backed key/value store at PATH, exposed to pages via cweb_database(). Sessions persist to it too.
--static-cache SECONDSCache-Control max-age on static files; ETag/Last-Modified still answer 304.
--etagStrong ETag (SHA-256) on every dynamic response; matching If-None-Match gets 304.
--request-idStamp every response (and req->request_id) with a unique trace id.
--request-id-inheritAlso echo an inbound X-Request-Id from a trusted proxy.
--basic-auth USER:PASSLock the app behind HTTP Basic auth.
--trusted-proxy CIDR[,CIDR...]Believe X-Forwarded-For only from reverse proxies in these networks.
--max-body BYTESRequest size cap, 413 past it; accepts k/m/g suffixes like 4k.
--body-dir DIRWith --max-body, spill oversized bodies to temp files in DIR instead of 413.
--max-inflated BYTESCeiling for a gzip request body after decompression (default 128m).
--tlsServe HTTPS with a self-signed cert minted under ~/.cweb and reused after.
--tls-cert FILE --tls-key FILEServe HTTPS with your PEM chain and private key.
--io-timeout MSPer-read deadline; stalled clients get 408.
--workers NAccept-loop worker threads; default is one per core.
--signature-secret SECRETRequire an HMAC-SHA256 request signature; anything else gets 403.
--socket PATHAlso serve the app on a unix socket at PATH (alongside the TCP port).
--cors ORIGINAnswer CORS preflights and stamp Access-Control-Allow-Origin. * opens it to any origin.
--csp POLICYContent-Security-Policy on every response, replacing the built-in default.
--csp-report-only POLICYA monitoring-only policy alongside the main one.
--log FILEAppend Common Log Format access lines to FILE.
--route-timeout PATH MSGive one route a per-request timeout (504 instead of 408 on a stall); repeat for more routes.
--routesPrint the route table and flags, then exit.
Note: everything these flags configure is also available directly through the library (router, session store, middleware chain), so a hand-written main.c can reproduce any of it. The generated server just mirrors the common setup in one line-flag form.
