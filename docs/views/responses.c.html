Responses

The Http_Response *res your handler receives is empty until you fill it. Pages mostly just emit markup through the template tags; the helpers below cover everything beyond that.

typedef struct {
    Http_Status status;       // HTTP_200_OK unless you change it
    Strbuf headers;           // raw "Name: value" lines
    Strbuf body;              // the payload
} Http_Response;

Status and headers

<?c
  http_response_set_status(res, HTTP_201_CREATED);
  http_response_set_header(res, "X-App-Version", "3");
  http_response_append_header(res, "Set-Cookie", "a=1; HttpOnly");
?>
  • http_response_set_header replaces any existing header of the same name (case-insensitive).
  • http_response_append_header adds a line without touching existing ones — for repeatable fields like Set-Cookie and Vary.

Redirects

Set a Location and pick a code from the RFC 7231 family (301/302/303/307/308; anything else quietly becomes 302). The classic POST-then-redirect is 303 See Other:

<?c
  http_response_redirect(res, HTTP_303_SEE_OTHER, "/notes");
  return;
?>

JSON

<?c
  Json_Value obj = json_make_object();
  json_object_set(&obj, "name", json_make_string("Ada"));
  json_object_set(&obj, "active", json_make_bool(1));
  http_response_json(res, HTTP_200_OK, obj);   // consumes and frees obj
?>
Note:http_response_json sets Content-Type: application/json; charset=utf-8, serializes the tree compactly, and frees it — the value is consumed, do not touch it afterwards. Parse inbound JSON with json_parse and read fields with json_get_*. See json.h for the full picture.

Already have the text? Use http_response_json_raw.

Cookies

Set cookies with an attribute bundle. SameSite=None forces Secure on, matching browser policy:

<?c
  Cookie_Attrs attrs = {
      .path = "/", .max_age = 3600, .http_only = 1,
      .same_site = COOKIE_SAMESITE_LAX,
  };
  http_response_set_cookie(res, "theme", "dark", &attrs);
?>

CORS

Let browser JS from a specific origin read the response, or open it wide with *. The Vary: Origin marker is added for you so shared caches keep variants apart:

<?c http_response_set_cors(res, "https://app.example.com"); ?>

For a preflight answer (methods, request headers, cache time):

<?c http_response_set_cors_allow(res, "GET, POST", "Content-Type", 600); ?>

Security headers

Stamp the baseline hardening headers — X-Content-Type-Options: nosniff, Referrer-Policy: no-referrer, X-Frame-Options: DENY — plus a Content-Security-Policy. The generated server does this for the whole app with --secure; use these directly to control a single route:

<?c http_response_security_headers(res, NULL); ?>  <!-- built-in CSP -->

Streaming

A response can stream a body instead of assembling it in memory. See Streaming for chunked output, SSE and WebSockets in detail. The short version for a pull-based body:

<?c
  http_response_set_stream(res, my_source, my_userdata);
?>

where my_source(buf, cap, user_data) fills buf and returns the byte count, or 0 when the stream is done.

Bodies that do not need the layout

When a layout wraps the app (see Pages), set res->no_layout = 1 to return this response naked — right for a JSON API or a download handler:

<?c
  http_response_json(res, HTTP_200_OK, value);
  res->no_layout = 1;
?>
