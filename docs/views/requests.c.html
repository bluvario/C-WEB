Requests

Every page handler receives an Http_Request *req describing the incoming request. Here is the shape of it:

typedef struct {
    Http_Method method;       // HTTP_GET, HTTP_POST, ...
    String_View target;       // raw target, query included
    String_View path;         // target without the query string
    String_View query;        // query string without the leading '?'
    String_View version;      // "HTTP/1.1" etc.
    String_View body;         // request body bytes
    String_View remote;       // peer address (the proxy's, behind one)
    String_View client_ip;    // real client, after trusted-proxy resolution
    String_View request_id;   // trace id, when the request-id middleware ran
    String_View auth_user;    // username, after Basic auth succeeded
    Http_Header_Array headers;
} Http_Request;

Method

Compare against the constants in http.h: HTTP_GET, HTTP_POST, HTTP_PUT, HTTP_DELETE, HTTP_PATCH, HTTP_HEAD, HTTP_OPTIONS.

<?c if (req->method == HTTP_POST) { ?>
  <p>Form submitted.</p>
<?c } else { ?>
  <p>Just rendering.</p>
<?c } ?>

Params: query strings, forms and route captures

The generated route handlers merge query string and form fields (both application/x-www-form-urlencoded and multipart/form-data) into params. Route captures (see Routing) are added last, so they win on a name clash.

<?c
  const char *q  = strmap_get_cstr(params, "q");            // ?q=...
  const char *id = strmap_get_cstr(params, "id");           // /notes/<id>
  if (q == NULL) q = "";
?>
<p>You searched for <?h= sv_from_cstr(q) ?></p>

By hand, and for anything params did not surface, use request_merge_params(req, &map) or parse the body yourself. Reading a raw header is case-insensitive:

<?c
  const String_View *ua = http_request_get_header(req, "User-Agent");
?>
<?c if (ua != NULL) { ?>
  <p>Your browser: <?h= *ua ?></p>
<?c } else { ?>
  <p>Unknown browser.</p>
<?c } ?>

Bodies

req->body is a String_View over the raw body bytes. For a JSON API, parse it with the JSON helpers; for form data, the params merge usually already did the work. When the server has a --body-dir, oversized bodies are spilled to disk and mapped back, so req->body behaves the same whatever the size.

If the body advertised Content-Encoding: gzip, the server inflates it up to the --max-inflated ceiling before your handler runs, and req->body points at the decompressed bytes.

Multipart uploads

File parts of a multipart form are not merged into params; you get them with multipart_parse and save them with multipart_save:

<?c
  Multipart m;
  multipart_parse(&m, req->body, boundary);
  for (size_t i = 0; i < m.count; i++) {
      if (m.parts[i].filename.count != 0) {
          char path[512];
          multipart_save(&m.parts[i], "./uploads", path, sizeof path);
      }
  }
  multipart_free(&m);
?>

The boundary comes from the Content-Type header via multipart_boundary.

Cookies

Parse the Cookie header into a Str_Map jar:

<?c
  Str_Map jar;
  strmap_init(&jar);
  const String_View *ck = http_request_get_header(req, "Cookie");
  if (ck != NULL) http_cookie_parse(&jar, *ck);
  const char *theme = strmap_get_cstr(&jar, "theme");
  strmap_free(&jar);
?>
Prefer sessions over raw cookies for anything you trust: a session token cookie only names a server-side bag, the client can never read or forge the data in it. See Sessions.

Validation

Form values arrive as strings; validating them is a common enough chore that the framework ships a small helper (validate.h):

<?c
  Http_Form f;
  http_form_init(&f);
  http_form_required(&f, params, "title", "Title");
  http_form_int(&f, params, "age", "Age", 0, 150, NULL);
  if (http_form_ok(&f)) {
      <!-- everything passed -->
  } else {
      http_flash_set(sesh, "error", http_form_error(&f));
  }
?>

http_form_value re-renders a field's submitted value into the response so a failed form does not wipe the user's input.
