Database

C-WEB ships a tiny file-backed key-value store. No daemon, no connection string, no schema, no query language — the whole file is slurped into memory, mutated there, and rewritten atomically on sync. Enough to persist counters, settings, notes, or anything else a page wants between requests.

Opening it

Run the generated server with --db app.db and every page can reach the shared store:

<?c
  Cweb_Db *db = cweb_database();
  if (db == NULL) {
      http_response_set_status(res, HTTP_500_INTERNAL_SERVER_ERROR);
      return;
  }
?>
Always check for NULL. cweb_database() returns the store only when the server ran with --db. Without it there is no store and the accessor returns NULL.

Reading and writing

<?c
  // write
  cweb_db_put(db, sv_from_cstr("visits"), sv_from_cstr("42"));

  // read — the view borrows from the db, valid until the next mutating call
  String_View v = cweb_db_get(db, sv_from_cstr("visits"));

  // delete
  cweb_db_delete(db, sv_from_cstr("visits"));
?>

Every operation serializes on an internal mutex, so pages running on different worker threads each get a coherent view.

When does it hit disk?

  • cweb_db_sync(db) writes now — atomically, via a temp file renamed over the path.
  • cweb_db_close(db) syncs then frees.
  • The generated server syncs on clean shutdown.

In practice pages rarely call sync: the framework decides. If you want a particular write durable immediately, sync it.

What the sessions store uses it for

Run with --db and the session store detaches persistence to the same file: sessions are mirrored under session-<token> keys as they change, and logins survive a restart. Your page data and the serialized sessions share one file — see Sessions.

Keeping it honest

The store is a deliberate trade: simple, embedded, atomic on sync, whole-file in memory. For a real relational workload — joins, indexes, concurrent writers across processes — put a database daemon behind a reverse proxy instead. The store is the persistence layer C-WEB needs, not a replacement for PostgreSQL.
